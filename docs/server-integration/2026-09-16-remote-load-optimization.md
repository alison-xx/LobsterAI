# 手机远控空闲负载优化接入说明

## 1. 变更摘要

本次同时降低桌面空轮询和服务端重复鉴权、空领取、WS 保活与回放成本。HTTP/WS 路径、请求字段、响应字段、错误码和能力协商协议保持兼容，默认远控功能仍开启；没有新增数据库迁移。

服务端空领取先检查是否存在候选，没有候选时省去领取事务的写入和锁；有候选仍进入原事务重新校验权限、设备、连接 generation 和租约。HTTP 只复用当前请求中已完成的 Bearer 验证，不缓存跨请求的账号状态。正常 WS 心跳合并 Redis 往返，心跳不查 MySQL；实际业务仍按当前连接内最长 15 秒的成功权限结果按需复核。服务端完整说明见 lobsterai-server 的 `docs/operations/2026-09-16-remote-control-load-optimization.md`。

## 2. 接口信息

以下路径均以 `/api/remote/v1` 为前缀。桌面 HTTP 请求继续携带：

```http
Authorization: Bearer <accessToken>
X-Remote-Device-Credential: <deviceId>.<deviceKey>
Content-Type: application/json
```

| 方法 | 路径 | 本次行为 |
|---|---|---|
| GET | `/devices/{id}/commands?state=unresolved&limit=100` | 沿用游标对账；空闲低频检查，收到通知立即检查 |
| POST | `/devices/{id}/commands/claim` | 领取最多 10 条，空结果是正常成功 |
| POST | `/devices/{id}/input-preparations/claim` | 每次领取 1 条，空结果不触发一秒重试 |
| GET / POST | `/devices/{id}/models`、`/devices/{id}/models/publish` | 未改变的本地模型目录在约 5 分钟内免重复远程核对 |
| GET / PUT | `/devices/{id}/agents` | 本地目录变化、重连及时发布，静态目录约 5 分钟核对 |
| GET | `/file-policy?deviceId={id}` | 策略约 5 分钟缓存；重连或策略版本错误失效 |
| POST | `/connection-tickets` | 沿用一次性 WS 连接票据 |

命令领取请求：

```json
{"connectionGeneration":"12","limit":10}
```

输入领取请求使用同样字段，`limit` 为 `1`。空领取响应保持原格式；`items: []` 不表示功能关闭或同步失败：

```json
{"code":0,"message":"success","data":{"items":[],"serverTime":"2026-09-16T08:00:00.000Z"}}
```

领票请求仍为 `{"protocolVersion":1}`，按既有能力协商可带 `projectionVersion`。从响应的 `data.wsUrl` 建连，格式为 `wss://<API_HOST>/api/remote/v1/ws?ticket=<single-use-ticket>`；不能复用已消费票据，不能在 URL 放长期令牌。

```json
{"type":"hello","protocolVersion":1,"connectionId":"conn_01","connectionGeneration":"12","heartbeatIntervalSeconds":30,"heartbeatTimeoutSeconds":90,"revalidateAt":"2026-09-16T08:15:00.000Z","serverTime":"2026-09-16T08:00:00.000Z"}
```

按 `hello` 的间隔发送和接收心跳：

```json
{"type":"ping","id":"ping_01"}
{"type":"pong","id":"ping_01","serverTime":"2026-09-16T08:00:30.000Z"}
```

服务端默认调整为 30 秒心跳、90 秒心跳超时、90 秒重连槽位保留。第三项是服务端的桌面重连占位保留时间，不是订阅回放间隔。桌面沿用 hello 协商，按 30 秒发送 ping、距上次 pong 达到 90 秒判为离线并重连，不强制覆盖服务端返回值。旧 hello 不含时间字段时仍按原 25/75 秒回退，因此新旧服务端均兼容。

`revalidateAt` 最长为领票后 15 分钟，仍受凭据到期时间限制。收到 `reconnect.required` 或连接关闭后重新领票，恢复订阅及原会话游标。`pong` 只说明连接存活，不能作为任务读取或执行授权成功的依据。订阅会话持久化回放仍有默认 45 秒补偿；正常通知及时回放，通知重复且游标已追平时省去重复查询。

## 3. 桌面与 App 接入事项

桌面本次实现如下调度，无需新增设置项：

- 命令对账和领取共享独立截止时间；空闲约 30 秒兜底，有待恢复命令或运行中任务时约 5 秒对账。当前账号 prepared / executing / unknown 命令，以及非终态运行（包含等待审批、等待本机操作、取消中、恢复对账中）均按活跃处理；其他账号的未决状态不影响当前账号调度。处理顺序保持对账、会话同步、输入准备、命令领取。
- 本次不延长命令有效期：启动任务命令上限仍为 60 秒，取消及审批等其他命令仍为 30 秒，并以接口返回期限为准。正常通知仍立即唤醒；若通知丢失且桌面处于空闲，30 秒兜底叠加抖动和网络耗时可能在领取前已过期；故障退避时也可能过期。等待审批等活跃状态采用 5 秒补偿有助于降低风险，但不能作为执行保证。App 继续按既有状态展示过期或失败，不把超时命令当作已执行，也不自动重放有副作用的命令。
- 输入准备独立调度，空结果约 60 秒后再领取，处理完成且可能有积压时立即继续；处理中的原 10 秒续租保留。命令满 10 条批次立即再检查，清空后恢复低频兜底。
- `commands.available` / `access.requested` 立即唤醒命令检查；服务端创建输入准备时向桌面发出的 `input.preparations.available` 立即唤醒输入领取，并清除上一次失败的输入退避。该通知携带 `preparationId`，例如 `{"type":"input.preparations.available","preparationId":"prep_01"}`。`input.preparation.updated` 原本用于通知手机状态变化，桌面仍保留兼容处理。流式回复、会话更新的同步唤醒不会每次同时查询两类队列。
- 领取失败、模型/Agent 目录核对失败、文件策略获取失败通常退避约 60 秒；普通同步唤醒不绕过失败退避，新输入可用通知可立即恢复输入领取。账号、连接 generation 或环境变化清除对应调度或缓存状态。
- 模型目录内容改变时，在后续本地检查中重新发布；未改变时约 5 分钟远程核对。已挂起的旧发布先按原 publicationId 完成，再发布新内容，不能将未发布的新目录误记为已同步。Agent 目录保留本地变更通知和重连触发。文件仍按原约 2 秒本地扫描，策略 GET 独立缓存。
- `/capabilities` 仍保留原 45 秒过期检查规则，在下一次 Bridge 周期执行，避免改变运行中能力协商和 Gateway 就绪检测语义。空闲主循环变低频后，实际获取间隔可能约 60 秒；它没有改为 5 分钟缓存。

上述时间不含网络耗时和原有少量调度抖动，不是时延 SLA。WS 通知正常时立即启动处理；通知丢失时靠低频对账补偿。App 不需要因本次优化新增字段或修改请求，仍需处理空列表、业务失败、重连和游标补齐。

## 4. 认证要求

继续使用现有 JWT Bearer、设备凭据、账号/空间归属及 generation 校验，Cookie 不能替代远控 Bearer。建连仍完整鉴权；心跳不延长业务授权。撤销或设备变化通知使服务端相关权限结果失效或关闭连接，实际任务请求仍必须通过业务校验。

服务端未收到撤销通知时，空闲连接可能保留到下次业务访问或凭据期限；业务正文不能靠持续 pong 绕过授权到期。桌面账号切换仍隔离本地会话所有者和远控队列。

## 5. 发布与验证注意事项

先小范围发布服务端，再发布桌面。服务端本次同时修复 `input.preparations.available` 和 `input.preparation.updated` 的 WS 转发：旧服务端遗漏这些通知，原桌面一秒轮询掩盖了问题。新桌面连旧服务端仍协议兼容，但新输入只能通过最长约 60 秒的空闲兜底发现，不能保证通知到达后立即开始；该时延不含网络故障和处理耗时。服务端更新期间也可能暂时落入低频补偿。旧桌面仍兼容，但只有升级桌面才能消除其空轮询。

滚动重启仍按既有持久化状态、重连和游标恢复，不要求增加网关或新部署组件。本次无新增 DDL，历史远控版本需要的迁移仍按原发布要求执行。

桌面无需新增配置。服务端共享 Redis 池新增有限借连接等待，默认 1,000ms，可由运维通过正数环境变量 `REDIS_POOL_MAX_WAIT_MILLIS` 调整；该参数不改变 App/桌面接入方式，也不是 Redis 操作总超时。功能开关默认值保持开启。

离线回归覆盖空领取不忙循环、无通知时 30 秒命令对账/领取与 60 秒输入领取彼此独立、等待审批和未决/恢复状态仍 5 秒对账、通知即时唤醒、30/90 秒 hello 协商与旧默认兼容、同步与领取解耦、积压继续领取、失败退避、重连/账号切换清理、模型旧 pending 与新内容并存、缓存重置期间旧响应隔离，以及文件策略缓存与失效；同时检查 Electron 类型编译及触及文件的 ESLint。本次没有执行压力测试，不能据此宣称已验证 10 万连接容量。发布后需观察空领取请求率、同步延迟、SQL/Redis 请求率与池等待，再验证真实设备负载。
